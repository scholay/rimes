# RIMES Windows 安装

Windows 11 x64；包括 x64/x86 TSF 和一个 x64 Broker。采用未签名 EXE 安装包，内置微软 VC++ 运行库。Windows 可能显示未知发布者或 SmartScreen 提示；安装器不会修改系统安全设置。真实宿主与一天试用需单独验收。

1. 下载当前版本的 `RIMES-Windows-版本-Setup.exe` 和对应 SHA-256 文件。
2. 在日常使用的 Windows 账号下双击 EXE，点击“安装 / 升级”，再同意管理员权限请求。输入法会自动停止，临时 Buffer 内容直接丢弃，不要求先保存或从托盘退出。可取消“登录后启动 RIMES”。若提示注销或重启，先保存其他应用的工作再执行；安装器不会自动注销或重启。标准用户可在权限提示中输入另一管理员账号的凭据；安装窗口继续以原账号完成词库部署、自启动与开始菜单入口。请从原账号启动安装器，不要先登录另一管理员账号运行。此跨账号流程适用于包含本次修复的新构建，旧安装包不会自动更新。
3. 用 Win+Space 选择 RIMES。在开始菜单搜索 **RIMES Settings**，或托盘右键打开设置，选择输入方案、简繁/标点、启动行为、API 和快捷键。在 **外观 → 尺寸** 中可设置候选字号、每页候选数（1–9）和竖向排列。每页候选数控制引擎分页；竖排在屏幕高度不足时自动分列，以保留全部候选。开始菜单入口会在升级或回退时指向当前版本；回退到不支持设置启动命令的早期版本时，移除该入口并提示从托盘打开。自己改过入口的目标或参数时，安装器会保留该修改。
4. 新设置默认在宿主输入框按 Ctrl+Shift+B 打开并绑定 Buffer；已有 Ctrl+Alt 等快捷键配置保留，可在设置中切换组合和字母。快捷键被占用时会提示，仍可从托盘打开；修改或保存失败时保留原快捷键。面板不激活，键盘继续留在宿主。点击“粘贴”只将剪贴板内容放入原文；点击“下一块”或轻按 Return 投递下一块，长按 Return 1.2 秒或点击“全部”投递当时队列。中文组字中的 Return 先处理组字。Ctrl/Alt/Win/AltGr 与 Return、Backspace、Escape 的组合仍交给宿主程序处理。
5. 从托盘打开后，先点击宿主输入框，再点击 Buffer 原文区开始输入（当前输入法需为 RIMES）。切换输入框、应用或输入法后，Buffer 暂停输入和投递；重新点击原文区，或在宿主按快捷键明确绑定。重复点击原文区不会关闭 Buffer。无可靠目标可复制。关闭面板保留本次进程内容；退出 Broker、注销或重启不会恢复正文。确认丢失时不重发，先检查宿主，再复制保留内容。
6. API 地址填到兼容服务的 API 根路径（例如 `https://example.com/v1`），程序追加 `/chat/completions`。模型可配置；修改 API 地址后需要重新填写密钥，旧密钥不会转发到新地址。密钥在凭据管理器 `RIMES.Windows.OpenAI`，设置文件不含密钥。使用“生成”或“翻译”会发送原文到你配置的服务。取消、编辑原文、切换配置会使旧请求失效。服务须提供 SSE 和 `[DONE]`；普通输入不等待网络。

上述快捷键与模式修复适用于当前源码构建，尚未包含在公开 1.1.1 安装包中。切回“输入”会停止自动翻译与排队请求，保留原文及已完成结果；保留结果仍须明确发送，继续编辑原文会使旧结果失效。

## 升级、回退、卸载

Buffer 是输入法内部 UI，临时正文不是持久化文档。更新、重装、回退、重置与卸载可直接丢弃临时 Buffer 内容，不要求保存、复制或手动退出。维护先预留输入法后台生命周期，阻止 TSF 在维护期间重新拉起后台，再自动停止经过路径、账号 SID 和进程身份校验的自有 Broker；新版正常关闭引擎，旧版无关闭接口或关闭超时时只终止自有后台。EXE 只切换注册到独立新目录；运行中的宿主若仍占用旧 DLL，会提示注销后生效。不会终止宿主，也不会强行覆盖旧 DLL。直接使用脚本时默认拒绝 DLL 占用，可显式传 `-AllowPendingRestart` 使用相同的注销后生效流程。词库、设置与凭据不按 Buffer 临时内容处理。

- 升级：运行新版本的 EXE。使用独立版本目录；注册失败尝试恢复旧版本。
- 验证：运行 `Verify.ps1`。核对两架构注册、文件清单、版本和提交。
- 回退：运行 `Rollback.ps1`，恢复 state.json 中记录的前一版。回退同样检查占用。迁移自旧的未打包安装时，恢复 `legacy-recovery.json` 记录的原始 DLL 路径与启动设置。
- 卸载：在 Windows **设置 → 应用 → 安装的应用** 搜索 **RIMES** 并点击“卸载”，或在控制面板 **程序和功能** 中选择 RIMES。从安装时的原 Windows 账号发起卸载并确认；后台会自动停止，不需要保存 Buffer 或从托盘退出。权限提示可使用另一管理员账号的凭据。注销两架构并删除自启动、安装的应用记录及安装器管理的开始菜单入口；保留版本文件和 `uninstalled-state.json` 供恢复。若宿主仍加载 DLL，卸载器会明确要求注销，不强行结束宿主。用户修改过的开始菜单入口会保留。
- 用户词库：`%APPDATA%\RIMES`；设置：`%LOCALAPPDATA%\RIMES\settings.json`。升级、回退、默认卸载均保留词库、设置和凭据。

初次部署完整词库可能较慢。诊断只包含版本、路径、错误类型和阶段，不包含 Buffer 正文、API 密钥或响应正文。不要把用户词库、设置和凭据放入问题报告。

## 脚本维护入口

需要手工验证、回退或卸载时，在安装目录的当前版本文件夹中，以当前用户打开管理员 64 位 PowerShell 并运行上述脚本。ZIP 保留为诊断产物；手工安装命令为 `powershell -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1`。逐文件校验信息保存在 PACKAGE.json。直接运行 `Uninstall.ps1` 默认拒绝 DLL 占用；保存工作后可显式传入 `-AllowPendingRestart`，采用与图形卸载入口相同的注销后生效方式。

EXE 安装分为系统和用户两个阶段。系统阶段负责运行库、版本文件、两架构注册及“安装的应用”记录；失败时尝试恢复系统注册和卸载记录。用户阶段在原账号下部署词库、设置自启动和开始菜单入口，并与正在运行的 Broker 互斥。若用户阶段失败，系统安装保留，原自启动和快捷方式恢复，界面明确提示尚未完成；从原账号再次运行同一安装器即可重试。卸载先保存并移除原账号的启动入口，系统注销取消或失败时恢复这些入口。同版本重装会修复缺失的系统入口。回退到没有图形卸载脚本的早期包时，继续使用保留版本目录中已校验的新版卸载器。

回退到早期包后请继续从 Windows“安装的应用”卸载，或运行卸载记录指向的新版 `Uninstall-App.ps1`；不要手工调用旧版目录中的原始 `Uninstall.ps1`，旧脚本无法清理新增的系统入口。

如果 `state.json` 丢失、损坏，或第三方卸载器删掉部分安装文件，请先运行包含恢复支持的新版本 `Setup.exe`。安装器从 RIMES 的实际两架构注册定位原版本，保留用户数据；同版本恢复只补齐缺失且清单匹配的文件。也可从完整且已校验的新版本 ZIP 运行 `Uninstall.ps1 -InstallRoot 原安装根目录`，清理实际注册指向的本项目残留。恢复不会按目录日期猜选版本；注册跨版本、指向安装根目录之外或文件校验失败时，会停止并说明原因。旧版 1.1.0 的恢复脚本不具备这些能力。

维护者可在源码仓库运行 `platforms/windows/tests/Test-InstalledAppsLifecycle.ps1 -OutputDirectory 新临时目录`，在管理员 64 位 PowerShell 中验证全新安装、升级、回退、部分失败和卸载规则。该测试只写临时文件及 `HKLM\SOFTWARE\Scholay\RIMES-Installer-Tests\随机ID`，使用假 TSF/Broker，不注册、停止或卸载正在使用的输入法。

`Test-RegistrarRecovery.ps1` 使用 CMake 测试目标 `RimesRecoveryRegistrar` / `RimesRecoveryTsf` 的专用 CLSID 验证真实两架构 TSF 注册及缺失 DLL 的清理。测试拒绝覆盖已经存在的测试注册，并核对正式 RIMES 注册和用户语言偏好保持不变；这些测试目标不进入发行包。

`Test-UninstallApp.ps1 -OutputDirectory 新临时目录` 无需管理员权限，在子进程执行当前图形卸载脚本，但用假对话框和假系统工作进程隔离确认、UAC 取消、失败恢复和完成提示，不会卸载本机输入法。系统阶段把确切的注销原因写入保留的 `uninstalled-state.json`，原账号的完成提示区分占用、缺失 DLL、旧安装待注销和损坏历史；记录缺失或不匹配时仍尊重 3010 返回码，保守提示注销。恢复记录写入失败时保留原状态并恢复注册。图形卸载入口也只使用 Windows PowerShell 系统模块目录，不继承 PowerShell 7 的模块路径。

## 离线安装与签名策略（#113）

安装包内置词库与 x64/x86 VC++ 运行库，普通输入和安装步骤没有下载依赖。AI 生成、翻译与后装插件需要其服务连接，不能据此认为输入法安装也必须联网。

EXE 启动内置 Windows PowerShell 时只使用系统模块目录，不继承 PowerShell 7 或用户自定义的模块搜索路径，避免校验命令缺失或被外部模块覆盖。系统模块仍须由 Windows 提供；安装器不会跳过文件校验。

若提权时出现“从服务器返回了一个参照”（Windows 错误 8235），先由内网管理员核对 UAC 的“仅提升签名并验证的可执行文件”策略（`ValidateAdminCodeSignatures`）以及代码签名信任链。错误发生在 Windows 启动提权工作进程的阶段，不足以证明安装器访问了服务器。当前公开未签名包不能满足强制受信任签名的策略；不要通过关闭 UAC、禁用该策略、跳过微软运行库签名验证或导入来历不明的根证书解决。应使用 IT 批准的签名包，在目标机器按组织流程预置受信任的证书链及所需验证材料。离线设备缺少微软运行库的信任链时，同样需要管理员修复证书部署；安装器保持拒绝无效签名。

维护者制作签名包时，`New-RimesNativePackage.ps1 -SigningCertificateThumbprint 指纹` 会检查原生文件的签名，并使用当前用户证书存储中该证书为外层 Setup.exe 签名、验证后再计算最终 SHA-256。单独调用 `New-RimesSetupExe.ps1` 时同样支持此参数；签名包不允许外层 EXE 默默降级为未签名。可显式指定 `-SigningTimestampServer http://组织认可的时间戳服务`，并验证时间戳已写入；Windows PowerShell 5.1 的该接口只支持 HTTP，时间戳数据由签名验证。构建时连接时间戳服务器不代表目标机器安装时要联网。提供完整链不会自动把证书加入目标机器的信任存储。

上述诊断和打包支持不是对 #113 原报告设备的验收。仍需原机器的策略/信任链信息、有效发布证书和内网实测。

## 跨账号维护与验收

`Install.ps1` / `Uninstall.ps1` 的 `-MachineOnly -UserSid 原用户SID` 仅执行系统阶段，不访问提权管理员的 HKCU、开始菜单或用户词库。安装归属写入系统状态与 Installed Apps；直接用另一个账号运行完整安装、回退或卸载脚本会被拒绝，避免接管原账号的安装。

托管版本的脚本回退可由管理员运行新版 `Rollback.ps1 -MachineOnly -UserSid 原用户SID`，然后由原账号运行新版 `Initialize-User.ps1 -ExpectedPackageDirectory 回退后的版本目录` 完成用户入口。词库保留；首次迁移前的未打包旧注册因缺少原用户启动快照，不支持跨账号自动回退，会在修改注册前说明。图形安装和卸载不需要用户手工执行这些命令。

EXE 在原账号下、提权之前创建有用户专属 DACL 的 Broker 生命周期预留锁，贯穿系统注册和原账号初始化；已运行 Broker 不再导致拒绝安装。该预留不持有互斥所有权；系统阶段自动停止经过校验的自有 Broker，部署子进程取得互斥所有权后部署词库。原 EXE 仍保留对象句柄直到自启动和开始菜单初始化结束，因此 TSF 不能在两个阶段之间抢先启动第二个引擎。图形卸载的原账号阶段也保留生命周期预留。并发安装仍拒绝，权限取消发生在后台停止前时不影响原后台；已进入系统阶段后发生错误仍恢复注册与启动入口，但不恢复已丢弃的临时 Buffer。字典互斥所有权仍被其他部署占用时拒绝开启第二个引擎；脚本直接初始化时先停止自有后台再取得部署锁。新版已缓存 TSF DLL 仅在其精确路径仍是当前注册时才可自动拉起后台；旧版缓存 DLL 不具备该检查，需要按卸载提示注销完成退出。

隔离回归覆盖不同 SID 的安装归属、系统阶段禁止访问用户配置、升级失败恢复、损坏状态卸载、用户初始化失败重试、Broker 部署互斥及取消卸载恢复。该回归使用测试注册表路径和假原生程序，不等同于标准用户在真实 UAC 中输入另一管理员凭据后的完整桌面验收。
