# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

## RIMES Design System Contract

- This project is the interactive React design source for RIMES. It documents and exercises settings, extension configuration, the candidate window, the Buffer workbench, and clipboard history.
- Match the current native product language: system typography, compact macOS density, the 经典 theme family (墨竹 / 翡翠 / 静谧 colorways), the independent 拉斯塔 theme, and the product-owned semantic tokens defined by `Sources/RimeBuffer/RimeUI.swift`.
- Keep production input behavior native. This React project may model focus, delivery, privacy, and plugin states, but it must never become the runtime IME window or introduce WebView dependencies into ETInput.
- Components must be built from shared tokens and reusable primitives. Avoid screen-local color, radius, spacing, and typography literals when a semantic token exists.
- Every primary control in the five showcase surfaces should work with realistic local state. No network or host-input access is required; Buffer result copy is the explicit exception and writes only the selected generated result through the browser's local clipboard API.
- Preserve the Sites-ready worker/build files so the design lab can be previewed locally or shared later without restructuring it.

## Confirmed Product Decisions

- Keep the input-source menu rooted at exactly six destinations: Settings, Buffer, Clipboard History, Mailbox, Capsule, and Maintenance. Buffer, Clipboard History, Mailbox, and Capsule are peer modules with independent windows and shortcuts; Buffer must not own the other three.
- The Capsule rail (formerly Clipboard History) is a standalone bottom-anchored nonactivating window opened with `Command+Shift+V`, not a Buffer rail. Its header tabs switch between Recent and read-only Capsule entries, and the Capsule manager opens only from its gear or the selected card's brush. It may open and retain activation authority only while the active input source belongs to RIMES. While capture is enabled and protection is absent, the native module persists text, links, images, files, and other lossless pasteboard representations in private local SQLite. Image records and decodable image-bearing files render bounded asynchronous thumbnails, cards show the real source-application icon when available, and localized image aliases participate in search; Shift plus a vertical wheel uses the reversed horizontal mapping. In its horizontal card timeline, a single click only selects; double-click, Return, or `Command+1`–`Command+9` activates. Text and links validate the exact focus token, insert through IMK, and move to the front. Images, RTF, HTML, files, and other rich records only restore the lossless system-pasteboard payload, move to the front, and close silently so the user can press `Command+V`. Never model or implement automatic Paste, context-menu actions, synthetic `Command+V`, Accessibility, or Post Event. `Command+C` restores the selected original representations and promotes them while keeping the window open; Delete removes, and Escape clears search before closing. Do not imply cloud or cross-device sync; history, source payloads, and previews remain local and never enter the repository.
- Keep core Input Method settings limited to Input Schemes and Dictionaries. The ordinary scheme catalog is Full Pinyin, Natural Code double pinyin, Xiaohe double pinyin, Wubi86, and English; do not restore the former Typing Mode page. Keep `builtin.fly-chord-learning` as the stable internal ID, but present it as the bundled `并击` 2.0 extension with Settings, Courses, Practice, and Progress. Its enable state is the sole gate for chord processing: Stream Input accepts chord-to-full-pinyin only while the extension is enabled, and otherwise remains sequential full-pinyin.
- Keep the current Buffer catalog limited to AI Generation 2.1, Real-time Translation 2.1, and Stream Input 1.3. Capsule is a first-class local module, never a Buffer plug-in: it owns Prompt, Memory, Password, Skill, Note, URL, Image, and PDF as local Markdown/encrypted records and exposes its own CRUD window with bounded media previews. Its optional user-selected iCloud Drive mirror syncs the six portable kinds and content-addressed media; Password, the master key, and Skill absolute paths remain local. Mailbox is likewise first-class; explicit Mailbox-to-Buffer handoff is optional interoperability rather than ownership. My Prompt, Remarkable, and Marine Chrome are retired from current cards, configuration branches, and Buffer modes.
- Keep Connectors limited to AI Models and Local Gateway. Show configuration and authorization details only for the selected AI connector; make the standard redacted MCP JSON the primary gateway setup and keep Claude Code registration behind optional disclosure. Remote Typing is retired and must not reappear in connector navigation or settings.
- The Buffer result-count contract is 1–5, the current design defaults to five results, and five-result presentation uses an in-rail pager. The native runtime now implements the same contract; future changes must keep the React design source and AppKit implementation synchronized.
- The Buffer design master may remain fixed at 760 logical points wide. Responsive width behavior is not required for this prototype unless the user revises this decision.
- Single-exchange is an accepted Buffer interaction pattern: a source rail may visually exchange into a result rail. Preserve both source and result state until delivery has been confirmed successful; a request or delivery failure must not discard either state.
- Buffer always shows the 33pt top toolbar plus 1pt divider. Ordinary/source-only/target-only states are 78pt and live source-plus-target states are 112pt. Do not restore a fold, chevron, or close control that hides the toolbar. Keep exactly one leading plugin glyph on the source rail; it is not a toolbar toggle. The toolbar contains the enabled-plugin selector, current plugin configuration, return-to-edit when relevant, status, and close. Do not restore a target-role icon or add a second leading plugin icon.
- Empty toolbar chrome, status, spacing, and flexible spacer are draggable; toolbar controls remain first-click interactive. Do not add a dedicated right-side 24pt drag strip or make the body/background draggable.
- Actionable progress, protection, failure, or delivery feedback has one visible owner: the active rail wins, and toolbar status is only a fallback when the rail does not already show it.
- The Buffer main action is a 22×22 icon-only control. Its visible icon changes with generation and delivery state, while its accessible label and tooltip retain the complete action or progress text.
- Every current generated target exposes one fixed copy action on the leading edge of the return/result rail, before the result text. It copies exactly the selected, current result through the local clipboard API and closes Buffer only after the write succeeds; it must never copy the retained source, sit on the trailing edge of the return box, or treat a stale result as current.
- Theme is a two-level model: `经典` owns the existing 墨竹、翡翠、静谧 colorways, while `拉斯塔` is an independent theme. Rasta must define the complete semantic token contract and visibly combine its red, yellow, and green brand roles rather than behaving as a single accent recolor.
- Keep candidate chrome limited to the numbered 1–9 candidates and the trailing Settings gear. The retired `0 + tray` control, its Buffer activation behavior, and its accessibility state must not return; an unmodified `0` remains available to the input engine/current text route.
- Controlled Buffer hosts must round-trip the `requestID` and `contextKey` emitted by `onGenerate`, keep `activeRequestID` aligned with the displayed result, honor generation/delivery `AbortSignal`s, and treat only an explicit `true` send acknowledgement as delivery success.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.
