# marine-chrome

`marine-chrome` 是 RIMES 的 Chrome Manifest V3 配套扩展。它把当前前台网页的短期上下文交给本机 RIMES，并在 Bilibili 视频页识别直评与精确回复目标。扩展不会向网页写字、点击发布按钮或代替用户提交内容。

## 安装

1. 构建并运行包含 `marine-chrome` 内置插件的 RIMES，确认“本地网关”已启用。默认地址是 `http://127.0.0.1:47700`。
2. 打开 `chrome://extensions`，开启“开发者模式”，点击“加载已解压的扩展程序”，选择本目录 `Extensions/marine-chrome`。
3. 扩展会自动打开连接页。Chrome 142 及更新版本可能询问“本地网络访问”，请选择允许。
4. RIMES 会弹出“允许 marine-chrome 连接？”；核对两边显示的六位确认码并点“允许”。
5. 回到扩展连接页，点击唯一一次出现的“确认连接”。内部凭据会自动生成并保存在扩展可信存储中，无需复制或填写任何密钥。
6. 在 RIMES 中启用并选中 `marine-chrome` 工作台，同时保持缓冲区处于可接收状态。

更新现有安装时，请先在 `chrome://extensions` 点击“重新加载”，再刷新所有已经打开的 Bilibili 视频页，让扩展从页面启动阶段开始监听评论接口；固定扩展 ID 没有变化时无需重新配对。曾被旧版本手动读取过的普通网页也请刷新；从未注入过扩展脚本的普通网页可在首次点击“读取当前网页”时直接使用。

### 从无固定 ID 的 0.1 开发版迁移

早期 `0.1.0` 开发版没有 `manifest.key`，Chrome 会按本机目录生成扩展 ID。后来即使目录中已经加入固定 key，扩展卡片上的“重新加载”也会继续沿用旧 ID，无法与当前 RIMES 配对。这个迁移只需做一次：

1. 打开 `chrome://extensions`，找到旧的 marine-chrome 并点击“移除”。
2. 点击“加载已解压的扩展程序”，重新选择当前仓库的 `Extensions/marine-chrome` 目录。不要只点击旧扩展卡片上的“重新加载”。
3. 在“地址诊断”中确认扩展 ID 为 `gpieknckmapliabifhgcedcjoigdjaah`，然后按连接页提示重新完成一次双重确认。

Chrome 按扩展 ID 隔离本地存储，因此旧 ID 下的内部凭据不会迁入固定 ID；重新确认一次是预期行为，之后同一固定 ID 的脚本更新和重新加载不再需要重复迁移。

## 使用

- Bilibili 视频页：聚焦主评论框会建立“直评”上下文；点击某条评论的“回复”并聚焦回复框，会建立带稳定评论 ID 的精确回复上下文。目标无法唯一确认时会拒绝建立回复上下文。
- 其他 HTTP(S) 网页：扩展不会常驻读取。点击工具栏图标，再点击“读取当前网页”才会用一次性的 `activeTab` 权限读取页面；有选区时优先发送选区，否则提取正文。
- 页面跳转、关闭、切到其他标签页、按 Escape 或评论编辑框失焦后，扩展会撤销上下文并取消未完成的读取。若仍是同一可见页面，但扩展弹窗拿走 DOM 焦点、正文/字幕尚未就绪，或 RIMES 暂时不可接收，扩展会保留本次读取意图。像旧 Marine 的宿主页绑定一样，手动读取与 Bilibili 直评每两秒只向 worker 发送不含正文的 URL 前台探针；worker 要求 main frame、document、tab、window、URL、epoch，以及 Chrome 最近选择的宿主标签全部一致，才重新提取并使用新的递增 revision。精确回复不使用这条放宽，恢复时仍必须重新确认当前 deep active editor 与评论 ID。已接受上下文每两秒续租；短暂中断后会重建新上下文。
- RIMES 工作台空态只显示一条生成轨；右侧状态区分别显示 Chrome 是否已配对、当前页面上下文租约、当前挂载来源是否为字幕，以及 AI 连接器是否就绪。“已配对”只代表本机授权关系存在，不等同于扩展此刻在线。

来源内容按顺序优先使用用户选区、字幕、已捕获评论和页面正文。Bilibili 只有标题或 URL 时仍保持读取意图，不会把元数据冒充正文；明确的视频简介才是可用 article。字幕首次为空时释放旧请求，并按 2/5/10/30 秒退避继续尝试，30 秒封顶；成功后按 BV/分 P 缓存并刷新当前上下文，隐藏页不发请求，导航后的迟到结果会被丢弃。评论目标只接受 DOM/API 中的稳定正整数 ID；超过 JavaScript 安全整数范围的 ID 必须来自原始字符串，不会由浮点数猜测或修复。

## 配对与隐私边界

- API 地址只接受带明确端口的 `http://127.0.0.1`，不允许远程主机、`localhost` 别名或 HTTPS 降级配置。
- 扩展通过仓库固定的 `manifest.key` 保持稳定 Chrome ID。固定 Origin 只做来源收窄，不被当作密码学认证。
- 首次配对使用 60 秒短期、绑定秘密的可重试 claim。RIMES 原生“允许”和扩展连接页“确认连接”缺一不可；连接页确认前即使收到成功响应也不会保存凭据。
- 内部凭据只存于受 `TRUSTED_CONTEXTS` 限制的 `chrome.storage.local`；若 Chrome 无法建立该隔离边界，扩展会停止连接。每次携带内部凭据前，扩展都会先用随机 nonce 验证 RIMES 返回的 HMAC-SHA256 身份证明，证明失败时不会发送凭据。
- 扩展没有 `<all_urls>`、剪贴板、下载、调试器、原生消息或自动发布权限。`dom` 权限只用于读取 Bilibili Web Components 的开放或闭合 Shadow DOM；本实现不会写入页面、点击控件或自动发布。Bilibili 自动脚本只匹配视频页；通用网页仅在用户点击后注入。
- 扩展明确禁止无痕模式，避免把无痕页面内容带入常规 RIMES 会话。
- 上下文只保存在进程内，租约新鲜度为 6 秒；RIMES 不是当前工作台、缓冲区不可用或处于安全/受保护输入状态时不会接收上下文。

日常重连只需打开扩展设置，按页面完成两次确认。若开发或恢复诊断需要主动撤销旧扩展并轮换全部凭据，可运行下面的命令；随后重新打开扩展设置完成确认，不需要粘贴命令输出：

```sh
swift run RimeBuffer marine-chrome-reset-pairing
```
