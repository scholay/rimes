# Buffer UI Notes

## Intent

The buffer is a native IME-layer staging area. It is not an AX/paste workaround and it is not part of Rime composition. Rime commits become blocks; blocks remain visibly staged until they are removed or flushed to the focused client through the normal delivery path.

## Current Shape

- `BufferModel` is an ordered block store, not an append-only queue anymore. A `Block` has stable `id`, `text`, `origin`, and `createdAt`. Rime commits establish block boundaries; accepted external text can also enter with provenance.
- Blocks can be inserted at `insertionIndex` or removed through explicit model operations. Workbench chips are passive and do not open a block editor. Live blocks are pending by definition because successful delivery consumes them.
- `BufferWindowController` owns the independent workbench. It is a borderless, nonactivating `NSPanel`, not a bottom-of-screen `BufferSurface`. On an explicit hidden-to-visible summon, it first settles any direct-host composition, grants Buffer capture to the exact current external `FocusToken`, establishes that lease's marked guard, reads one fresh token-validated caret line rect, and places the current-height panel exactly 10pt below that rect or above it when needed. The external field remains only the later delivery anchor: opening the workbench changes logical input ownership to Buffer without making the nonactivating panel key. The maximum possible workbench height, including the optional Clipboard rail, forecasts a side that stays safe without creating invisible spacing; the independently floating candidate panel never contributes to workbench geometry. No exact target uses a lower-center fallback on the mouse screen. It never follows later caret/focus updates while visible. A zero-width caret is valid, but zero, nonfinite, implausibly tall, off-screen, own-window, stale-token, or secure-input targets are not. Contextual workbench-height changes grow away from the input line: below-target keeps the panel's top edge fixed and above-target keeps its bottom edge fixed. Automatic opening origins remain transient: user dragging persists the manual frame, while launch/session restoration remains passive. The toolbar is always expanded: ordinary and single-exchange states are 78pt; live source-plus-target layouts are 112pt. Alternative count never changes the base panel height. Manual and lower-center layouts retain the historical fixed-bottom behavior. Width defaults to the React master width of 760pt and remains adjustable, while the former tall preview layout is gone. Toolbar gaps and its flexible empty space may initiate `performDrag`; every `NSControl` keeps first-click behavior, and neither the panel background nor the content rails may drag. Visibility, frame, and pin-to-all-spaces are persisted in UserDefaults; the retired controls-expanded and candidate-placement preferences are ignored.
- Visibility recovery is the sole exception to “never follows later focus.” While capture remains enabled, a newly trusted exact external text focus may relocate the existing panel once when it is stranded on another macOS Space or when a plausible caret is on another physical display. Same-display field changes, typing, and streamed updates never move it. Revalidate the exact token, secure input, and session protection immediately before ordering the panel. Without plausible caret geometry, preserve/clamp the existing frame and only re-order it; never use the explicit Show action's mouse-screen fallback. Unpinned behavior is `.moveToActiveSpace + .fullScreenAuxiliary`; pinned behavior is `.canJoinAllSpaces + .fullScreenAuxiliary`, and the two Space modes remain mutually exclusive. The automatic origin stays transient. Closing the workbench pauses capture, so enabled capture is the authoritative visibility intent and may repair an obsolete hidden preference.
- The ordinary main row is exactly `BufferInlineView` plus one explicit 22×22 icon-only primary action. It shows a paper plane for delivery, sparkles when generation may be requested, and a spinner while generating; it never renders a visible “发送” or “生成” title, while its tooltip and accessibility label retain the full action description. There is no drag-handle or expand/collapse affordance. The permanently visible toolbar has fixed action slots plus a conditional 88pt status column: the status column is detached completely while empty and appears only for actionable work, protection, focus blockers, or failures. Inline Rime preedit already communicates composition at the Buffer caret, so the toolbar never repeats it as a visible “正在组字” status. One activity message has exactly one visible owner: when a body target/status rail renders it, the toolbar status stays empty; only a state not rendered in the body may use the toolbar fallback. The remaining toolbar contains the compact buffer-plugin selector plus selected-plugin actions, flexible drag space, optional privacy-safe contextual indicators, a conditional 22pt return-to-edit control, and close. Hidden loading indicators and empty plugin-action rows detach from layout so the shared selector surface has no blank trailing segment. Routine idle/ready prose is blank and creates no leading reservation. Settings independently enables any number of `.bufferAction` plugins; the selector lists only that enabled set, gives every entry a compact SF Symbol, and uses `Default` for the explicit no-plugin owner. Selecting an item atomically replaces the unique owner without changing the enabled set. Internal lifecycle restart/reset never clears staged text for live-expand workspaces or external actions. The AI single-exchange result instead exposes return-to-edit as an explicit result-discard action; no user-visible refresh control exists. Pin, move, and the underlying buffer enable/disable control remain available from Settings/the input-source menu, not the workbench. There is no block editor, in-panel capture switch, manual privacy-eye, history/restore, or clear/undo control. When direct routing owns the exact focus, the ordinary Rime candidate surface follows that host caret. When Buffer owns the same exact token, `BufferInlineView` projects Rime preedit at the logical insertion caret and the same `CandidateWindow` remains an independent nonactivating panel that floats with that caret; the candidate panel shows candidates only, never occupies a workbench row, and never changes the 78/112pt Buffer layout. Preedit projection and candidate content share the same token-owned Rime context without creating a second selection authority, and both are scrubbed before secure-input or session hiding. Derived alternatives still page inside their separate target rail and are not Rime candidates. An ordinary close resolves current composition if safe, pauses capture, clears transient loading/error state, preserves staged blocks, and hides.
- Apple Translation and 意识流输入 use live-expand presentation: source and one independently scrolling target rail remain visible together. The renderer accepts one to five mutually exclusive alternatives, keeps exactly one stable target viewport, and pages the selected alternative instead of stacking rows; host semantic segmentation may still create multiple delivery chips inside the active alternative. Current providers may return fewer than five. AI 生成 uses single-exchange presentation: idle shows the retained source rail, while waiting/result shows one target rail. The visual swap never mutates either workspace value. Source and every unsent result remain owned by the concrete workspace until explicit successful host delivery, or until the user explicitly chooses return-to-edit and discards that result. Rail roles are SF Symbols with accessibility labels, never the visible Chinese markers “原/译/答/拼/文/搜/词”. AI 生成 uses the independently selected Codex CLI, Claude Code CLI, or 通用 Open API（OpenAI 兼容）connector. 意识流输入 instead owns focus-bound raw full-pinyin outside BufferModel/Rime and always uses the user's saved OpenAI-compatible configuration directly, independent of ordinary connector selection; the current configured model is `deepseek-v4-flash`. The primary action stays in one fixed target-side slot while alternatives page.
- My Prompt, Remarkable, and Marine Chrome are retired product integrations. Their isolated compatibility code and smoke commands may remain in the source tree for migration/history, but they must not enter the current preset catalog, runtime owner selector, release assets, or required release gate. Do not describe them as current capabilities or add new product work to them.
- AI 生成 and an external owner whose entire resolved action surface is one prepared presentation are explicitly generated, never automatic-on-type. Neither has a separate expanded-shelf Generate button: the right-side primary action is a disabled AI icon when unavailable, an enabled AI icon when generation can be requested, a spinner while running, and a paper plane when matching final blocks are ready. Return uses the same state machine; request/running/disabled own the entire press on keyDown, while ready retains tap `sendNext` / 1.2-second hold `sendAll`. Any legacy compatibility presentation keeps the complete explicit shelf so Return never guesses. An internal AI generation freezes current source text and source block identities; source remains through generation and partial delivery, and is consumed only after every target block has been delivered successfully.
- 意识流输入 keeps the selected ordinary input scheme unchanged. Its chord route is owned only by `ChordExtensionStore`: with the optional Chording extension disabled, physical `a-z` remains continuous per-letter full-pinyin raw regardless of the selected Rime schema; with the extension enabled, it freezes the extension's FlyYao mode and stages the current alphabet with `FlyChordBatchState` and `ChordSettings.duration`, decodes the deployed `my_combo` mapping order-independently, and atomically writes mapped full pinyin. Chord mode maps only the current batch; mutual mode may additionally replace an immediately preceding left-only batch plus the next right-only batch when at least one side is multi-key and the schema/focus/raw/soft-offset snapshot still matches exactly. A complete both-halves syllable appends a real ASCII Space tagged in a sidecar as a soft syllable boundary. Unpaired one-sided mappings such as `dv→n` and `km→ong` are pinyin fragments and append no separator. A single letter stays literal, two singleton batches never recombine, lone comma/period is owned but ignored, and an unmapped multi-key batch preserves deterministic letter raw without inventing a separator. The first staged key immediately revokes any old delivery lease. Disabling the extension, non-chord input boundaries, focus, secure-input, owner, configuration, or workspace invalidation must tombstone both the batch timer and mutual pairing snapshot.
- 意识流输入 is the intentional automatic exception. Its saved response preset is fast 140/500 ms, balanced 220/800 ms (default), or stable 350/1200 ms debounce/max-wait, and its saved candidate limit is 1–5 (default 5). Each real request freezes both values together with the complete raw snapshot; later preference changes affect only the next request. Each settled letter/chord mutation resets only the selected debounce, while the max-wait deadline established for the current typing burst does not move. A chord-inserted soft Space renders as an ordinary source-rail space and follows normal debounce. A user-entered Space records one normalized ASCII hard short-sentence boundary, renders as `·`, and immediately requests the current complete raw snapshot; when it follows a trailing soft Space it promotes that byte in place instead of inserting another. Leading/repeated hard spaces do not create work. Continuing after a hard Space still receives the normal trailing debounce request for the newest complete raw. Other punctuation remains consumed and ignored outside chord batching. It should return one result for clear input and add alternatives for meaningful ambiguity; when local hints contain more than one reading, the payload sets `minimumGuessCount=2`, capped by the frozen limit. A valid undersized final gets one bounded retry whose JSON-encoded untrusted payload excludes the first validated guesses; terminal results are merged in original-first order, exact-deduplicated, and capped by that same frozen limit throughout prompt, provider schema, decoder, partial, final, retry, and fallback handling. If that optional retry repeats or fails, keep only the preceding verified final ready instead of falsely reporting invalid format or authorizing a retry partial. A first request with no strictly valid terminal fallback still fails closed on malformed, empty, or oversized output. Never split one intended sentence across alternatives. Digits `1`–`5` and plain Up/Down change the unconfirmed selection; modified arrows remain host commands. Return keyDown or the paper plane atomically confirms the selected row and deletes its peers before any insertion. The same Return tap then sends the next semantic block and a 1.2-second hold sends every remaining block of that selected answer; alternatives are never concatenated.
- Stream inference uses bounded make-before-break, never unbounded fan-out. At most an older visual producer and one newer challenger may overlap. Typing a newer raw value immediately revokes every old result/delivery lease but does not cancel issued requests on each key. At a debounce, max-wait, Space, or Return boundary, start the newest complete snapshot when a slot is free; keep the prior visual producer until the challenger emits its first validated nonempty snapshot or reaches a terminal result, then tombstone/cancel the older request. If both slots are occupied, keep only one latest-only pending marker; when a slot opens it captures the then-current complete raw instead of replaying an obsolete queued snapshot. Provisional output and the baseline are display-only: never include either in a later prompt, show either as selected while waiting/running, or make either deliverable. The sole prompt exception is the same-revision, one-shot minimum-candidate retry: only its preceding strictly validated terminal guesses may appear as bounded, JSON-encoded, explicitly untrusted exclusion data; partials, carryover, and results from another revision remain forbidden.
- Every 意识流 request carries the complete raw-pinyin snapshot plus its frozen soft-space offsets and asks for a fresh global interpretation; never infer only the newly typed suffix or concatenate separately inferred regions. A bounded local syllable lattice supplies up to three lossless advisory boundary readings: hard Space renders as ` | `, soft Space remains an ordinary pinyin syllable boundary, and uncertain English/typo spans are preserved. Above 512 bytes it omits hints rather than duplicating a large raw value. It never generates Chinese or partitions model inference. Only hard-Space-separated nonempty clauses establish a minimum delivery-block target; soft chord separators never force output segmentation. When the model omits punctuation, split further only at safe boundaries and never cut an English word, URL, code span, number, or quotation merely to reach that target. Reuse stable candidate-slot identities and reconcile each new partial in place from its common prefix; retain the inert baseline while a divergent replacement is still shorter than four readable characters, then replace in place. The current-raw final response is authoritative and must exactly replace its generation's slots; no baseline tail, prior generation, or separately inferred region may enter a ready/deliverable block. Confirmation prunes peer alternatives immediately, while raw survives partial delivery and clears only after the selected answer's final block succeeds; typing a letter or Space after the first delivered block deliberately drops the unsent tail and starts a fresh raw value.
- Codex CLI and Claude Code CLI are local process launches, not local inference: clicking Generate sends the current buffer text through the service authenticated by the installed CLI. Except for an explicit fail-closed `RIMEBUFFER_CODEX_PATH` override, Codex discovery must prefer ChatGPT.app's bundled executable and then continue to the first compatible Homebrew/PATH candidate; its ChatGPT credential remains isolated under `~/Library/RimeBuffer/ai/codex-home` and never comes from `~/.codex`. Claude readiness must be derived only from the official `claude auth status --json` `loggedIn` result; Settings may launch/cancel `claude auth login --claudeai`, but RimeBuffer must not read Claude credential files or pass `CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CONFIG_DIR`, or ambient API keys to the child. Capability/auth probes run off the IMK main thread with stale-while-revalidate caching; Generate verifies the cached executable's stat fingerprint before source text is prepared. Both providers fail closed before source text leaves RimeBuffer unless the exact executable passes the prompt-free capability contract: Codex must complete an isolated app-server initialize plus empty-MCP handshake, and Claude must advertise every tool-disable and streaming option used for generation. Compatible releases are accepted regardless of version number. The 通用 Open API（OpenAI 兼容）connector is configured with Base URL, model, and API key under Settings › Connectors › AI Model. 意识流的 `.alternativeGuesses` request explicitly sends `thinking: {type: disabled}`, JSON-object response mode, `max_tokens: 1024`, and low temperature; ordinary AI generation does not inherit these provider-specific controls. Its private JSON is `~/Library/RimeBuffer/ai/openai-compatible.json`, mode 0600; the key must not enter UserDefaults or logs. The `ai` directory is product-owned state outside the app bundle and must survive development reseeding, pkg overwrite installs, and in-app updates so users do not have to re-enter the configuration.
- `Command+Shift+B` is the process-global workbench toggle. When hidden it invokes the open-and-resume behavior, bringing the panel to the active Space and granting the exact current external focus to Buffer before further typing. The host field remains the delivery anchor but is no longer the logical input surface. When visible it invokes the ordinary close-and-pause behavior, resolving composition safely, preserving blocks, stopping transient work, and pausing capture. The registered hot key is consumed and must not leak `B` to the host.
- A real input-source transition away from the RIMES parent or one of its modes uses the same close-and-pause lifecycle after retiring the focus lease and candidate surface. Staged blocks are preserved, capture and transient plugin work stop, and returning to RIMES does not reopen the workbench. Duplicate TIS notifications that repeat the same non-RIMES source ID still fail closed by retiring any residual focus/candidate authority, but do not repeat the stateful workbench close.
- `Command+Shift+P` is the configurable process-global Clipboard-rail toggle. It enables and reveals the rail in the shared nonactivating shell, or hides only that rail when already visible. Revealing Clipboard may call `show()` but must not call `openAndResume()` or otherwise change `BufferModel.enabled`; the exact hot key is consumed and must not leak `P` to the host. If an enabled rail is ordered on another Space, the first press brings it to the active Space rather than disabling it unseen.
- Unmodified Escape closes and pauses any visible shared workbench, whether Buffer capture is active or the shell is Clipboard-only. A Buffer-owned composition may be settled through the normal close lifecycle; a Clipboard-only/direct route must not force-commit, cancel, or mutate host composition. Duplicate or stale Escape callbacks are consumed without closing a mismatched authority or leaking to the host.
- While an exact external buffer lease is active, exact Command+Shift+Up/Down cycles backward/forward through the popup's same ordered `Default + enabled buffer plugins` catalog and wraps at both ends. Extra modifiers, own-window focus, and secure input retain native behavior.
- `BufferWindowGeometry.clampedFrame` restores off-screen frames, chooses the screen with greatest intersection, clamps width to the selected screen, and defaults to the always-expanded ordinary/single-exchange 78pt or live-expand 112pt base height. Enabling the optional Clipboard rail adds one 40pt row plus a 1pt divider, producing 119pt or 153pt. Rime preedit and candidates never add workbench height: preedit is inline in the existing source rail and the candidate panel is an independent WindowServer surface. Explicit collapsed values remain only for legacy-frame migration tests. Manual and fallback height transitions preserve the window's bottom edge. Runtime min/max sizes are resynchronized per screen after move/resize.
- Clipboard history is a separate, explicit opt-in workbench rail, not the Control/Command+V source-edit path. It is disabled by default and reads `NSPasteboard` only while the rail is enabled, the nonactivating workbench is physically visible on the active Space, and secure input, lock-screen, sleep, and inactive-session protection are all absent. An explicit user off-to-on transition may capture the current eligible plain-text item once when the shell is visibly on the active Space after that action. It stores bounded text only in the current process (30 items, 64 KiB per item, 512 KiB total), never UserDefaults/disk/logs; protected or hidden intervals stop at `changeCount`, and ordinary show/hide or protected/session resume establishes a new baseline without backfilling protected-time content. A user gesture may add the selected item only through `BufferModel.insertPastedText`; it never writes the system pasteboard, enables Buffer capture, retains a client, or calls `Delivery.insert` directly. Privacy discard clears the process-local items; ordinary hiding preserves them until process exit.
- `BufferWindowGeometry.openingPlacement` is the pure explicit-summon rule: a plausible fresh caret selects its own screen, horizontally centers the current-height panel on the caret, uses the maximum workbench height (base rails + Clipboard) only to forecast a stable side, and places the real frame 10pt from the input; no valid caret uses the fallback screen's lower center. The fresh host rect must come from `attributes(forCharacterIndex: 0, ...)`: that index is inline-session-relative and must never be replaced by document-relative `selectedRange.location` or `markedRange.location`. `resizedOutward` preserves the near edge during workbench rail changes. Candidate placement is a separate geometry transaction anchored to the currently visible logical caret.
- `RimeBufferController.drainCommit` remains the routing point: direct route means `Delivery.insert`; exact Buffer capture means append the commit to `BufferModel`. Preedit remains transient and never enters a stored block: direct input uses the host marked-text caret, while exact Buffer capture projects it inline at the `BufferInlineView` insertion caret. In both routes the single `CandidateWindow` remains a detached panel and follows the active caret.
- While buffer mode is on, plain or Shift-modified Return and Backspace are always consumed by the input method, including engine-failure or untrusted-focus paths. A Return press with pending Rime/chord composition or a stream raw value that is not ready only settles/forces that source and suppresses the rest of the same physical press. A ready stream final instead confirms and prunes alternatives on keyDown, then uses that same physical tap/hold gesture. Otherwise a tap requests `sendNext` and a hold of about 1.2 seconds requests `sendAll`; Backspace edits active Rime/chord state or removes a buffer block only when precise focus is trusted. Neither key may fall through to the host text field.
- Exact Control/Command+A and Control/Command+V edit the workbench source for ordinary buffering and every plugin. Ordinary, Translation, AI, and Action/Marine modes select all `BufferModel` source blocks; paste inserts at the block caret or replaces the complete selection while preserving exact concatenated text before semantic segmentation. Stream mode selects only raw source, never candidate rows. Its paste accepts only ASCII letters plus whitespace, lowercases letters, normalizes whitespace runs to real ASCII Space boundaries, and immediately requests the complete new raw. Any other character or a normalized total above 16 KiB rejects the entire stream paste without changing raw, selection, alternatives, generation, or provider work. Ordinary clipboard text must be nonempty, NUL-free, and at most 1 MiB. Extra Shift/Option, Control+Command, and own-window shortcuts remain native. Secure input passes the shortcut through before any pasteboard access; an untrusted external focus consumes it without reading. Native AppKit clients may translate physical Control+A/V into `moveToBeginningOfParagraph:` / `pageDown:` before IMK sees a key event; recognize those command-only aliases only while the matching exact physical chord is still down, and recover an implicit callback client only from the fully revalidated live lease plus current controller-client identity. For an exact trusted lease, reinstall the invisible marked-text guard after settling real preedit and before source mutation or pasteboard access, then revalidate the same lease after that synchronous host call and after a potentially lazy pasteboard provider returns. This per-key guard prevents Chromium/Electron from both updating the workbench and executing the same native shortcut in the host field.
- A standalone Shift tap shorter than 500 ms keeps the schema's existing ASCII-toggle behavior. The controller defers the Rime Shift pair until physical release and replays the saved left/right keysym only after proving the gesture was a same-session/schema standalone tap. If Shift participates in another key (including controller-owned direct punctuation, buffer Return, stream capture, a shortcut, a pre-held modifier, or the other Shift), remains held for at least 500 ms, or crosses focus, neither mode-switch event is sent. This prevents `commit_code` side effects as well as preserving the prior Chinese/English mode.
- While an exact external buffer lease owns those controls, `CompositionSession` keeps one invisible U+200B marked-text guard alive even when Rime is idle. It reasserts that guard on every owned idle Return and exact Control/Command+A/V action before the host can observe the handled result. This prevents Chromium/ProseMirror hosts from submitting raw Return or repeating the native clipboard shortcut when a host silently ended an earlier marked session, without changing the existing short-press/long-press decision. Guard lifetime is independent from semantic Rime composition: idle guard means `composition.composing == false`, `FocusLease.compositionActive == false`, and `markedRangeReliable == false`. Every Return action synchronously checks secure input first: a secure press is consumed without composition settlement, U+200B reassertion, AI generation, or delivery. Transient external content otherwise uses the idle guard but keeps real Rime preedit inline; own-window focus, focus loss, or buffer deactivation removes the guard.
- `BufferDeliveryCoordinator` is the only component allowed to turn staged blocks into `Delivery.insert` calls. Keyboard delivery passes the `FocusToken` captured on Return keyDown; the explicit paper-plane control at the right end of the main row is also a current-focus `sendNext` action. The window never retains or calls an `IMKTextInput` directly.
- Switching the current buffer-plugin owner cancels in-flight work but is not an authority-revocation event for already completed Action Plugin blocks. A completed Marine block must retain the runtime binding, action, context, and focus validation minted when it was generated; disabling, uninstalling, or upgrading that external plugin still revokes those grants.
- A send starts from `InputFocusCoordinator.liveTarget()`. The lease must have the current and expected `FocusToken`, an external target, trusted delivery state, live controller/client, a `controller.client()` whose object identity still matches the lease, matching client bundle, and a frontmost application whose process PID (plus bundle when available) matches the lease. There is no recent-controller or last-client fallback.
- If composition is active, the coordinator may explicitly resolve it, then must reacquire the same expected token. It revalidates that target, composition state, and secure input before every block, stopping immediately if focus changes.
- A successful `Delivery.insert` call is only an accepted attempt, not a destination ACK, but the current product contract consumes that accepted block from the live buffer immediately. A failure stops the operation; the failed block and every not-yet-sent block stay in place.
- Accepted deliveries are consumed from live `blocks` without retaining a plaintext delivery history. There is no user-facing clear/undo path; automatic privacy discard remains an irreversible safety operation.
- Automatic flushing and timer-based deletion remain disabled. Return tap/hold and the paper-plane button are deliberate user actions; the paper plane is one-block only, while an accepted `insertText` attempt consumes the corresponding live block synchronously even though the target app does not provide a stronger acknowledgement.
- The default-on “close after last delivery” preference applies to `Default` and every Buffer plugin, but it is a post-transaction visibility action, never automatic delivery. Close-and-pause only after the exact final pending block succeeds, its source is atomically drained, the generation and workspace owner/session still match, no new source content appeared, and the original target remains live. A disabled preference, partial failure, generation/content drift, owner/session switch, or target loss keeps the workbench open.

## Display Requirements

- Show block boundaries because they are meaningful Rime commit boundaries.
- Keep current model order and the insertion point visually clear; explicit insertion means it is not always strict creation-time order.
- Show provenance for non-Rime blocks. The live rail contains pending blocks only; do not render sent checks or other sent-state decoration.
- Make long block text inspectable with a tooltip while keeping each individual rail row single-line.
- Keep passive text blocks dense without shrinking the 12pt text: use a 3pt gap between blocks, 4pt horizontal and 1pt vertical content insets, a 20pt block height, and 5pt rail-side insets. Apply the same density to ordinary, preedit, message, and translation blocks while preserving provenance and independent scrolling.
- Keep stream-input alternatives visually continuous across whole-raw generations: retain provisional old-job text and the handoff snapshot only as a visibly stale, noninteractive baseline until same-index partials can update stable slots in place. Never blank the target rail merely because raw changed or a newer request started. Waiting/running output has no selected treatment and no delivery lease; only a final whose raw/job/generation is still current may become selected and sendable.
- Keep first-click controls working inside nonactivating panels by using controls that accept first mouse.
- Give every enabled workbench button and popup an explicit hover/pressed surface plus a pointing-hand cursor using tracking that remains active in the nonactivating panel. Disabled controls keep the arrow and no hover surface. Only toolbar chrome that is not occupied by an `NSControl` may drag; passive buffer chips remain non-draggable and never imply clickability.
- Keep the plugin selector compact and compressible. Store a complete domain-qualified `PluginKey` in each item rather than deriving identity from menu indices or raw IDs; rebuild it on the next main-loop turn after registry/selection notifications so AppKit never loses the item currently dispatching its action.
- Keep the plugin selector pinned to the leading inset. The 88pt status column participates only for actionable blockers, active operations, protection states, or failures; detach it completely for routine ready/idle so no empty leading reservation remains. A permanent flexible spacer after plugin actions must absorb status/action width changes, provide the primary empty drag region, and keep the conditional 22pt return-to-edit control plus close at the trailing edge. There is no refresh slot.
- Show Return hold progress as a 2px accent line along the bottom of the always-visible rail without changing panel height; clear it on release, cancellation, focus change, or secure-input shielding.
- Show Rime candidates through one regular `CandidateWindow` state machine and one native panel content hierarchy, with the same theme, metrics, paging, and token-owned actions in both routes. Direct input anchors that detached panel to the current host caret. Exact Buffer capture projects preedit inside the Buffer source rail and anchors the same detached panel to the Buffer logical caret; it never reparents candidate content into the workbench. The panel uses `.moveToActiveSpace + .fullScreenAuxiliary`; if AppKit still reports an already visible panel on an old Space, order it out before the next `orderFrontRegardless()`. Never clone candidate selection state or introduce a second candidate authority. Stream alternatives remain pages of the derived target rail and do not use `CandidateWindow`.
- Treat an ordered panel on another macOS Space as not currently visible. An explicit Show action may re-order the unpinned strip onto the active Space; enabled capture may do the same once after a newly trusted external text focus proves the panel is stranded. A valid caret on another physical display may similarly trigger one recovery move. Neither path activates RimeBuffer or makes the panel key.
- Keep ordinary, source-only, and target-only single-exchange base states at 78pt; live source-plus-target stays 112pt whether it owns one or five alternatives. Page alternatives inside the one target rail instead of changing base height. Long text should truncate or scroll instead of resizing the panel off screen. A contextual opening must keep its input-facing edge 10pt from the original caret line and grow outward; manual/fallback layouts keep the bottom edge stationary. Exact Buffer capture does not add a composition row: preedit stays inline in the existing source rail, while the detached candidate panel sizes, flips, and clamps independently around the Buffer caret. Geometry must still fit visible frames narrower than the normal minimum.
- Inset the rounded chrome inside a transparent window margin, fill it with the fixed 墨竹/翡翠 workbench surface token so HUD backdrop sampling cannot reduce text contrast, and draw the border as a backing-scale hairline inside its path. Do not center a layer border on the window bounds, where macOS clips it into fuzzy corner/edge fragments.
- Keep queued content visible even if buffer mode is switched off; do not hide unsent text.
- Treat the empty source copy in Default and every derived Buffer as a placeholder, not input content. Show it only while the logical input is inactive and both source/preedit are empty; after a source-rail click successfully grants exact Buffer input ownership, remove it from layout and show the caret alone at the empty insertion point. Loading, failure, target-result, and protection messages remain explicit state rather than placeholders.
- Keep an empty state visible when buffer mode is on but no blocks exist; an active empty input is represented by its caret rather than placeholder text.
- Shield staged text plus candidate/delivery rails while secure input is active. Hide the workbench and revoke its target while the desktop session is inactive, locked, or asleep. There is no separate manual privacy-shield state.

## Safe Extension Points

- Add read-only presentation properties to `BufferModel`, such as grouped counts, source summaries, ages, or pending-delivery summaries. Keep mutation in explicit model methods so identity, provenance, order, and notifications stay coherent.
- Add richer single-line presentation to `BufferWindowController`/`BufferInlineView`, but route send actions through `BufferDeliveryCoordinator` and candidate actions through the token-owned `CandidateWindow` state machine.
- Add transformations by deliberately creating a new derived block with explicit provenance; do not silently mutate a passive workbench chip.
- Add a new generated two-rail plugin through a `BufferDeliveryContentSource`-compatible workspace: freeze source text/block IDs, invalidate stale generations, keep streaming block identity stable, and consume source only after the last target block succeeds.
- Add visibility, placement, or appearance settings through `SettingsWindow` and UserDefaults. Reuse `BufferWindowGeometry.clampedFrame` for restoration and add tiny-screen cases whenever geometry rules change.
- Evolve focus handling through the pure `FocusTargetRules`, `FocusEventRules`, and `FocusActivationRules` predicates. Any relaxation must retain exact-token ownership, event ordering, lifecycle attribution, external-target filtering, lease/client plus `controller.client()` identity checks, and frontmost bundle/PID checks, with matching `buffer-window-smoke` cases. Pending chord callbacks must be isolated before a lease is suspended or displaced.
- Add another delivery destination only behind an explicit routing layer. Local text insertion must still end at `Delivery.insert`, and a multi-block operation must stop rather than switch destinations when the original token becomes stale.
- Add persistence for buffer text only as an explicit privacy/product decision. Current content is intentionally process-local, and delivery history is intentionally not retained.
- Do not add automatic or delayed delivery outside the explicit Return gesture and paper-plane actions. A keyboard gesture must retain the keyDown token, deliberately settle any intervening composition without sending in the same press, and revalidate that exact token immediately before every insertion.

## Do Not Do

- Do not write buffer content directly to clients from `BufferWindowController` or `BufferInlineView`.
- Do not restore `active ?? recent`, `lastClient`, or bundle-only target fallbacks. The frontmost PID check is required because an app can relaunch with the same bundle identifier.
- Do not flush through an unresolved composition. Only `BufferDeliveryCoordinator` may resolve it for a user-initiated send, after which it must reacquire the same token.
- Do not let Return or Backspace escape to the host while buffer mode is enabled, even when Rime is unavailable or the focus lease is untrusted. Return delivery may occur only through the tap/hold state machine; repeats, late keyUp/command callbacks, focus changes, and composition-settling presses must never create an extra send.
- Do not implement timer-based deletion or automatic delivery. Consuming a block is part of the synchronous user-initiated successful delivery transaction; failure must leave that block live.
- Do not treat “CLI runs locally” as a local-inference privacy guarantee, put source text in CLI argv, invoke a shell, log provider output, or persist an API key in UserDefaults.
- Do not clear completed Action Plugin delivery bindings merely because the workbench owner changes; conversely, do not preserve them across disable, uninstall, upgrade, or runtime-identity failure.
- Do not make the passive panel key by default.
- Do not reintroduce diff/reconcile logic from old `buffer-bar`; commit boundaries are already known.
- Do not put preedit into the buffer. Composition preview belongs to marked text and/or candidate window.
- Do not persist buffer text/history accidentally while adding window preferences; those have a different privacy lifetime.
